# Разбор: шесть поломок, которых не видел ни один тест

> Разбор работы, доехавшей в `main`: браузерная прогулка по всем режимам игры и
> шесть поломок, которые она нашла. Написано так, чтобы читалось и без знания
> кодовой базы — раздел «Что было» можно пропустить, если вы её знаете.

---

## Что было

### Совсем сначала

«Мафия» здесь живёт в браузере и состоит из трёх частей.

`server.js` — сервер на чистом Node без единой зависимости. Он раздаёт статику из
`public/`, держит комнаты в памяти и говорит с клиентом двумя способами: REST для
действий (нажал кнопку — послал POST) и SSE для пушей (сервер сам присылает новое
состояние стола, когда за столом что-то произошло).

`server/game.js` — движок партии. Автомат состояний: фаза (`night`, `morning`,
`speech`, `day`, `vote`, `lastword`, …), список игроков с ролями и `tick()`,
который сервер зовёт раз в секунду. Ключевой метод — `viewFor(userId)`: он
собирает для каждого игрока **его личную** картинку мира. Чужие роли в неё просто
не попадают, поэтому подглядеть в сетевом трафике нечего.

`public/js/online.js` — клиент. Он получает из `viewFor` объект `game`, внутри
которого лежит `you` — всё, что игрок знает про себя: роль, партнёры, поданный
голос и, самое важное для дальнейшего, `canAct`: одно слово, означающее, что от
него сейчас ждут (`kill`, `heal`, `vote`, `speak`, `talk`, `listen`, …).

> [!NOTE]
> **`canAct` — это контракт между сервером и экраном.** Сервер говорит «от тебя
> ждут голоса», клиент рисует голосование. Всё, что игрок видит на экране партии,
> выводится из этого слова: подсказка внизу, набор кнопок, подсвеченные места. Мы
> ещё вернёмся к тому, что бывает, когда `canAct` пустой, а подсказка об этом не
> знает.

### Сцена и вкладки

Стол рисуется двумя способами. Плоская сцена (2D, canvas) — по умолчанию;
объёмная (3D, WebGL, three.js) — по кнопке. Обе живут внутри одного контейнера
`.stagewrap`, и поверх сцены **HTML-слоями** лежит всё остальное:

```
#stage        сама декорация (canvas)
#marks        подписи мест — HTML поверх сцены, чтобы текст был резким
.phaseband    планшет фазы: название, счёт живых, таймер
.actiondock   подсказка и кнопки решения
.rolepane     панель роли
.finale       занавес с итогом партии
.flatwrap     плоский список мест — «стол» для телефона и запасной вид без WebGL
```

Порядок этих слоёв задан руками, через `z-index`. Запомните это место: там и была
самая дорогая поломка.

На телефоне рядом ничего не стоит — там пять вкладок внизу (Сцена, Стол, Роль,
Чат, Протокол), и `openPanel(which)` показывает по одной.

### Что проверялось до этой работы

Тестов было много и они были хорошие: девятнадцать блоков, от арифметики состава
до симулятора баланса на тысячи партий. Два из них поднимали настоящий браузер:
`e2e-smoke.js` смотрел на стартовый экран, `e2e-play.js` играл партию целиком.

Обе браузерные проверки знали **ровно одну страницу** — `public/bots.html`. Ту, в
которой лежит старый отдельный движок игры с ботами. Всё, чем сайт живёт сейчас —
воронка на главной, комната по сети, стол с соседями, «Следствие», вход по
ссылке-приглашению, — не открывалось браузером ни разу. Ни один тест не нажимал
кнопку «Играть».

И ни один из них не входил в `npm test`.

## Интуиция

### Тест, который ходит, а не читает

Все девятнадцать блоков проверяли **правила**: сколько мафии на двенадцати
игроках, кончится ли партия, не уйдёт ли фаза в вечное ожидание при обрыве связи.
Это ровно то, что тестируется без браузера, и потому именно это и было
протестировано.

А поломки, которые нашлись, устроены иначе. Ни одна из них не про правила. Все
шесть — про то, **что человек видит и куда может нажать**:

| Правила говорят | Игрок видит |
|---|---|
| фаза `day`, `canAct: 'talk'`, кнопка «Я высказался» отрисована | пустой экран со списком людей |
| `canAct: null`, потому что игрок мёртв | «Голосование: выберите того, кого город выводит» |
| комната по ссылке `?join=abc` открыта | «вернитесь на главную и назовитесь» |
| кнопка чата отрисована и подписана | пустой квадрат 44×44 |

Отсюда идея нового теста: он не читает исходники, а ходит путями живого игрока и
на каждом шаге задаёт три вопроса, которые вместе и значат «играбельно».

1. **Нет ли ошибок?** Консоль, необработанные исключения, упавшие запросы.
2. **Видно ли, что делать?** Есть название фазы, есть подсказка — и если
   подсказка чего-то требует («выберите», «назовите», «передайте»), то на экране
   обязано быть чем это сделать: кнопка или выбираемое место.
3. **Влезает ли в телефон?** Ничего не уехало за край, нет горизонтальной
   прокрутки, нет текста мельче 11.5 пикселей, нет кнопок без знака и без
   подписи, нет зон нажатия меньше 30 точек.

Третий вопрос стоит пояснить на примере, потому что «нет кнопок без знака» звучит
как придирка к стилю. Вот проверка целиком:

```js
const BLANK_CONTROLS = () => {
  const bad = [];
  document.querySelectorAll('button, a.btn').forEach(el => {
    const cs = getComputedStyle(el);
    if (cs.display === 'none' || cs.visibility === 'hidden') return;
    const text = (el.innerText || '').trim();
    const svg = el.querySelector('svg, img, canvas');
    if (!text && !svg) bad.push('#' + el.id);
  });
  return bad;
};
```

Она нашла `#btnChat` — кнопку чата в шапке. Всю партию, на каждом телефоне, в
шапке висел квадрат 44×44 пикселя, в котором не было ничего. Никакой тест на
исходники этого поймать не мог: разметка кнопки правильная, `aria-label` на
месте, обработчик клика есть. Не было только знака — потому что рисовать его
никто не звал.

### Слой, который съел таймер и все кнопки

Самая дорогая находка. Разберём её на числах, потому что вся суть в одной строке.

```css
.phaseband { z-index: 4 }   /* фаза, счёт живых, таймер */
.actiondock{ z-index: 4 }   /* подсказка и кнопки решения */
.finale    { z-index: 20 }  /* занавес с итогом партии */
.flatwrap  { z-index: 70; background: var(--ink) }   /* плоский список мест */
```

Семьдесят больше четырёх. И больше двадцати.

На телефоне `.flatwrap` — это вкладка «Стол», и открывают её постоянно: именно там
видны имена, роли выбывших и пометки, а на сцене при двадцати игроках только
номера. Пока она открыта, `.flatwrap` растянут на всю сцену (`inset: 0`), залит
непрозрачным цветом и лежит выше всего остального.

Значит, игрок, открывший стол, терял:

* название фазы и **таймер** — он выбирал человека, не видя, сколько осталось;
* весь док действий — а в нём кнопки «Я высказался», «Передать слово»,
  «Воздержаться», «Поднять всех»;
* занавес финала: если партия кончалась, пока открыт стол, итог оказывался под
  столом, и это выглядело как зависшая игра.

И не только глазами. `.flatwrap` перехватывал и нажатия — он же лежит сверху:

```
elementFromPoint(центр кнопки «Передать слово») → #flatWrap
```

То есть кнопка была не просто невидима, а физически недоступна.

Лечится это не подкручиванием одного числа, а тем, чтобы вообще перестать
считать `z-index` в уме. Порядок слоёв выписан один раз, словами, в комментарии
над правилом — и с тех пор его держит тест:

```
сцена 0 · подписи 1 · плоский стол 6 · планшет фазы и док 8 · панель роли 9 · финал 20
```

### Приглашение, которое исчезало

Друг присылает ссылку `https://сайт/online.html?join=1-pG2skRJIXm7lxy`. У
пришедшего имени ещё нет — в этой игре нет ни почты, ни пароля, но имя есть, и
без него за стол не сажают.

Что он видел:

> **Нужно имя**
> Чтобы играть по сети, вернитесь на главную и назовитесь.
> [На главную]

Он идёт на главную, называется — и приглашения больше нет. Оно было в адресной
строке, а адресную строку он только что заменил. Чтобы всё-таки сесть за стол,
надо вернуться в переписку и открыть ссылку второй раз; догадаться до этого можно,
но это самый дорогой отказ на сайте, и он стоял ровно в том месте, куда приводит
единственный способ позвать друзей.

Интуиция починки: **не уводить человека оттуда, где лежит контекст**. Имя
заводится на месте, страница перезагружается тем же адресом, `?join=` цел:

```
было:   ?join=abc → «уйдите на / и назовитесь» → / → назвался → приглашения нет
стало:  ?join=abc → назвался здесь → reload(?join=abc) → за столом
```

### Кадр, который считался ни для кого

Две вещи, которые видно только с секундомером.

Первая. Подписи мест — это HTML, а сцена рисуется в canvas, поэтому каждый кадр
надо спрашивать у сцены, где сейчас чья голова, и двигать подписи:

```js
function frame(now) {
  requestAnimationFrame(frame);
  placeMarks();          // ← двадцать проекций и двадцать записей в стиль
  ...
}
```

На телефоне подписи видны **только на вкладке «Сцена»** — на четырёх остальных
`#marks` спрятан. А `placeMarks()` всё равно исправно считал их положение шестьдесят
раз в секунду. Стол на двадцать человек — это тысяча двести проекций и тысяча
двести записей в стиль в секунду, которые никто не увидит.

Вторая. Плоская сцена не рисует свёрнутую вкладку — так и было задумано:

```js
if (document.hidden) return;   // телефон в кармане не должен греться
```

Объёмная — рисовала. Полный проход WebGL с тенями, затенением и размытием по
глубине, пока телефон лежит в кармане.

## Код

### 1. Тест, который ходит по режимам — `tests/e2e-modes.js`

Новый файл, восемь разделов. Каждый — путь живого игрока: главная и воронка,
быстрая игра в одно нажатие, стол с соседями, комната по ссылке, партия целиком,
«Следствие» целиком, статика и SEO, правила, и отдельно — «телефон в руках».

Устройство простое: сервер поднимается на своём файле аккаунтов, для каждого
экрана снимается «замер» (`PROBE`) и снимок, а после раздела печатается сводка.

Одна деталь стоит объяснения, потому что она отличает полезный тест от
надоедливого. Первая версия ругалась на широкую таблицу правил, уехавшую за край
экрана на телефоне. Но таблица лежит в прокручиваемой обёртке — до правого края
доезжают пальцем, и это честное решение, а не поломка. Тест, который заставляет
ломать работающее, хуже отсутствия теста:

```js
/* Широкая таблица внутри прокручиваемой обёртки — не поломка, а решение. */
const inScroller = el => {
  for (let p = el.parentElement; p && p !== document.body; p = p.parentElement) {
    const o = getComputedStyle(p).overflowX;
    if (o === 'auto' || o === 'scroll') return true;
  }
  return false;
};
```

Из того же ряда — галочки настроек. Сама галочка 20×20, и тест честно сообщал о
слишком мелкой цели. Но галочка лежит внутри подписи, а вся подпись нажимается и
имеет 44 пикселя высоты: палец попадает в строку, а не в квадратик. Мерить надо
ту область, которая реагирует на касание, — `el.closest('label')`.

А главная проверка «видно ли, что делать» после починки подсказок сформулирована
так, чтобы говорить именно о поломке, а не о непохожести на образец:

```js
/* Экран «немой», когда подсказка требует действия, а сделать его нечем.
   Честное ожидание («слово у Клима», «вы вне игры») — не поломка. */
const canDo = st.actions.length > 0 || st.pickable > 0;
const demands = /выберите|назовите|передайте|скажите|голосуйте|решите/i.test(st.hint);
if (!canDo && demands) mute.push(key + ' | ' + st.hint);
```

### 2. Слои сцены — `public/online.html`

Одно число и комментарий на десять строк, объясняющий, почему оно такое:

```css
/* СЛОИ СЦЕНЫ. Плоский стол лежит НАД декорацией и подписями мест, но ПОД
   планшетом фазы, доком действий, панелью роли и занавесом финала. …
   сцена 0 · подписи 1 · плоский стол 6 · планшет и док 8 · роль 9 · финал 20 */
.flatwrap{ position:absolute; inset:0; z-index:6; … }
```

`.phaseband` и `.actiondock` поднялись с 4 до 8, `.rolepane` с 3 до 9, `#marks`
получил явную единицу вместо `auto`. Заодно выяснилось, что верхний отступ
`.flatwrap` в 70 пикселей был предусмотрен как раз под планшет фазы — и всё это
время был бессмыслен, потому что планшета там не было видно.

### 3. Кнопка чата — `public/js/online.js` и `public/online.html`

Знак кнопке рисует новая функция, которую зовёт `paintTabs()` — то есть на каждом
обновлении вкладок:

```js
function paintChatBtn() {
  var b = $('btnChat');
  if (!b) return;
  var open = state.panel === 'chat';
  setHTML(b, ico('chat', 20) + '<span class="lbl">Чат</span>');
  b.setAttribute('aria-pressed', open ? 'true' : 'false');
  b.title = open ? 'Закрыть чат стола' : 'Открыть чат стола';
}
```

Второй половиной той же поломки была строка в CSS. Кнопка должна быть видна
только внутри партии и только на узком экране, и это было записано так:

```css
#btnChat{display:none!important}
@media (max-width:900px){ #btnChat{display:inline-grid!important} }
```

Скрипт при этом честно ставил и снимал атрибут `hidden`, а в дизайн-системе есть
`[hidden]{display:none!important}`. Но `!important` с идентификатором сильнее
`!important` с атрибутом — и на любом экране до 900 пикселей `hidden` не работал
вовсе. Кнопка чата висела в шапке и в лобби, и на экране «нужно имя», где ей
нечего открывать.

Правило переписано наоборот — так, чтобы `hidden` остался главным:

```css
@media (min-width:901px){ #btnChat{display:none!important} }
```

> [!IMPORTANT]
> Это не единичная опечатка, а класс ошибок: **CSS, который отменяет решения
> скрипта.** Тест гигиены теперь ищет любое `display:…!important` по
> идентификатору — такое правило почти всегда означает, что где-то рядом
> перестал работать `hidden`.

### 4. Имя на месте — `public/online.html` и `public/js/online.js`

Экран «Нужно имя» стал экраном входа: поле имени, кнопка, кнопка «сесть гостем» и
ссылка на главную последней, а не единственной. Заголовок заодно перестал быть
`«Нужно имя»` и стал `«Мафия по сети»` — это ведь единственное, что видит на этой
странице поисковый робот, у которого аккаунта нет.

```js
/** Завести имя и вернуться на этот же адрес — вместе с приглашением. */
function claimName(name, btn) {
  name = String(name || '').trim();
  if (name.length < 2) { API.toast('Имя от 2 до 16 символов', 'bad'); return; }
  btn.disabled = true;
  btn.setAttribute('aria-busy', 'true');
  API.call('/api/register', { name: name })
    .then(function (r) { API.save(r.user); location.reload(); })
    .catch(function (e) { API.fail(e); btn.disabled = false; btn.removeAttribute('aria-busy'); });
}
```

`location.reload()` вместо перехода — весь смысл починки: адрес остаётся тем же, и
`?join=`, `?solo=`, `?quick=` доживают до второго прохода.

Пришедшему по ссылке текст говорят другой — тот, который отвечает на его вопрос:

```js
if (lede && (q.get('join') || q.get('room'))) {
  setText(lede, 'Вас позвали за стол. Назовитесь — и вы сразу окажетесь в комнате: ' +
    'приглашение никуда не денется, почта и пароль не нужны.');
}
```

### 5. Подсказка, которая знает, кто её читает — `hintFor`

Три правки в одной функции. Первая — выбывший:

```js
/* Выбывший читал те же подсказки, что и живые: «Голосование: выберите того,
   кого город выводит» — при том что выбрать он ничего не может. Человек в
   этот момент решает, что игра сломалась. */
if (you.alive === false && g.phase !== 'lastword') {
  return 'Вы вне игры и уже всё знаете. Стол вас не слышит — говорить можно ' +
    'в канале выбывших. Смотрите, чем кончится.';
}
```

Исключение для `lastword` обязательно: там выбывший как раз и говорит.

Вторая и третья — про поданное решение. Экран после нажатия выглядел точно так
же, как до него, и человек жал второй раз:

```js
if (you.myVote) {
  return (you.myVote === 'skip' ? 'Вы воздержались.' : 'Ваш голос подан.') +
    ' Передумать можно до конца отсчёта — выберите другого.';
}
```

### 6. Адреса, которые разворачивает сервер — `server.js`

В файлах лежит `/img/og-image.png`, и это правильно: домен площадки в исходниках
знать неоткуда. Но четыре тега такой относительности не переносят — `og:image`,
`twitter:image`, `og:url` и `canonical`. Ни одна соцсеть не разворачивает
относительный путь к картинке: превью не собирается вообще ни одно.

Домен у сервера уже был — из него давно собираются `robots.txt` и `sitemap.xml`.
Осталось подставить его и в разметку:

```js
const ABSOLUTE_META = /(<(?:link|meta)\b[^>]*?(?:rel="canonical"|property="og:(?:url|image)"|name="twitter:image")[^>]*?\b(?:href|content)=")(\/[^"]*)"/g;
const ABSOLUTE_LD = /("(?:url|image|item|@id)"\s*:\s*")(\/[^"]*)"/g;
```

Второе выражение — про структурированные данные: `url` и `image` у `VideoGame`,
`item` у хлебных крошек Google читает как ссылки, а не как строки.

Заодно у страниц появилась метка версии. До этого HTML уходил с `no-cache` без
`ETag`, то есть **целиком на каждый переход** — а `bots.html` это 320 килобайт по
мобильной сети:

```js
const tag = '"' + st.size.toString(36) + '-' + Math.round(st.mtimeMs).toString(36) +
  (html ? '-' + hashOf(siteOrigin(req)) : '') + '"';
if (req.headers['if-none-match'] === tag) {
  res.writeHead(304, { ETag: tag, 'Cache-Control': cacheFor(file, ext) });
  return res.end();
}
```

Метка считается из размера и времени правки файла — считать хэш от трёхсот
килобайт на каждый запрос было бы дороже самой пересылки. Домен входит в метку
отдельным слагаемым: содержимое страницы от него теперь зависит, и за прокси
иначе отдавался бы чужой адрес.

### 7. Телефон: кадр, шапка, главное действие

Кадр перестал считаться вхолостую — две строки в двух файлах:

```js
// online.js, placeMarks()

// stage3d.js, frame()
```

Сброс `last = 0` здесь не косметика: без него счётчик кадров после возвращения
увидел бы один огромный интервал и решил, что железо слабое, — а он на это

### 8. Два мёртвых правила каскада — `public/bots.html`

Их нашла не прогулка, а собственный вывод `e2e-play.js`, который до этого никто
не запускал. Обе — один и тот же промах: правило для узкого экрана написано
**выше**, а ниже в том же файле тот же селектор с той же специфичностью объявляет
то же свойство. Побеждает позднее объявление.

```css
@media (pointer:coarse){
  .panelClose{width:44px;height:44px}      /* строка 407 */
}
...
.panelClose{width:30px;height:30px}        /* строка 508 — и она сильнее */
```

Рядом с первым правилом лежал комментарий «на сенсорных экранах делаем
полноценный квадрат 44×44». Правка была написана, объяснена — и не работала:
крестик закрытия панелей оставался 30 пикселей в ширину при 44 в высоту.

Второй случай хуже, потому что виден на глаз. Док переключения панелей
объявлен `display:none` и включается медиазапросом на узком экране; но вторая
копия правила ниже включала `display:flex` **безусловно** — и в углу настольного
экрана висели два телефонных переключателя «Моя роль» и «Протокол», при том что
обе панели на столе и так открыты.

Чинится переносом: всё, кроме `display`, объявлено один раз в базовом правиле, а
медиазапросы остались единственными, кто это правило меняет.

### 9. Чем это теперь держится — `tests/test-assets.js`

Тест гигиены страниц вырос на пятнадцатый раздел. Каждая проверка в нём стоит на
месте настоящей поломки — они держат не «стиль», а конкретные вещи, которые
игрок видел на экране:

* битые символы ищутся обходом по каталогам, а не по списку файлов (файл,
  забытый в списке, — это ровно тот файл, в котором битый символ и живёт);
* нет `display:…!important` по идентификатору, перебивающего `hidden`;
* ни одна правка в медиазапросе не отменена ниже по каскаду;
* плоский стол ниже планшета фазы, дока, панели роли и финала — числа сравниваются;
* на экране без имени есть поле имени и кнопка;
* ровно один `h1` на страницу (заголовки внутри `<noscript>` не считаются: они и
  есть единственный заголовок, когда скриптов нет);
* сервер разворачивает адреса и отдаёт метку версии.

Проверка мёртвых правил — единственная сколько-нибудь хитрая: она считает
вложенность фигурных скобок, находит границы всех `@media`, и для каждого правила
внутри проверяет, не объявлено ли то же свойство того же селектора ниже и вне
медиазапросов. Правила с `!important` пропускаются — такое переспорит и позднее.

## Альтернативы

### Слои сцены: `z-index` или порядок в разметке

Поломку со съеденным доком можно было чинить иначе — не числами, а порядком: вынести
`.flatwrap` в разметке выше планшета фазы и дока и убрать `z-index` у всех
четырёх, оставив естественный порядок наложения.

| Порядок в разметке | Явный `z-index` (выбрано) |
|---|---|
| Нельзя ошибиться в числе: порядок один и виден в разметке | Числа надо держать в голове или в комментарии |
| Не нужен комментарий про слои — их видно | Нужен комментарий, иначе следующий поставит 70 снова |
| Переставлять разметку рискованнее: меняется порядок обхода с клавиатуры и для читалок | Разметка не двигается, поведение с клавиатуры не меняется |
| Работает только пока никто не добавит `position` с `z-index` посередине | Держится тестом, который сравнивает числа |

Выбран второй вариант ровно из-за третьей строки: `.flatwrap` — это список из
двадцати кнопок, и переносить его в обходе клавиатуры перед планшетом фазы ради
косметики CSS не стоит. Риск, что кто-то снова поставит 70, снят тестом.

### Абсолютные адреса: сервер или сборка

Домен можно было подставлять не на выдаче, а один раз — шагом сборки или просто
`SITE_URL` в файлах.

| Шаг сборки / фиксированный домен | Разворот на выдаче (выбрано) |
|---|---|
| Нулевая цена на запрос | Регулярка по HTML — но результат кэшируется на домен и время правки файла |
| Появляется шаг сборки там, где его не было ни одного | Ни одного шага сборки не появилось: `node server.js` и всё |
| Домен надо где-то прописать руками и не забыть при переезде | Домен берётся из запроса — работает на любом хосте и за прокси сразу |
| Локальная разработка и продакшн расходятся | Одинаково и там и там |

Проект специально собран так, что запускается одной командой без зависимостей —
и вторая строка перевесила остальное. `SITE_URL` при этом поддержан: если он
задан, берётся он.

## Проверьте себя

<details>
<summary>1. Почему кнопка «Передать слово» на вкладке «Стол» была не просто невидима, а не нажималась?</summary>

- **а)** У неё стоял `disabled`, пока открыт стол.
- **б)** `.flatwrap` растянут на всю сцену (`inset: 0`) и лежит выше дока по
  `z-index`, поэтому все нажатия в этой области доставались ему. ✓
- **в)** Обработчик клика навешивался только на вкладке «Сцена».
- **г)** Кнопка отрисовывалась внутри `#marks`, а `#marks` был спрятан.

Правильный ответ — **б**. Элемент выше по `z-index` перехватывает не только
взгляд, но и события: проверка `elementFromPoint(центр кнопки)` возвращала
`#flatWrap`, а не саму кнопку. Именно поэтому починка — про порядок слоёв, а не
про обработчики. Вариант **а** неверен: `disabled` док не ставил; **в** и **г**
описывают механизмы, которых в коде нет.
</details>

<details>
<summary>2. Почему `#btnChat` оставался виден, хотя скрипт исправно ставил ему <code>hidden</code>?</summary>

- **а)** Атрибут `hidden` не работает на элементах с `display: grid`.
- **б)** `setHTML` перезаписывал разметку кнопки и терял атрибут.
- **в)** `#btnChat{display:inline-grid!important}` в медиазапросе сильнее
  `[hidden]{display:none!important}`: у обоих `!important`, но у первого
  специфичность идентификатора против атрибута. ✓
- **г)** Медиазапрос стоял ниже в файле, а при равной специфичности побеждает
  позднее правило.

Правильный ответ — **в**. Когда `!important` есть у обоих правил, спор решает
специфичность, и идентификатор её выигрывает у атрибута. Вариант **г** описывает
другой класс ошибок — тот, что нашёлся в `bots.html` с `.panelClose`; там
специфичности были **равны**, и потому решал порядок. Вариант **а** неверен:
`hidden` — обычное правило `display:none` в таблице браузера, его перебивает
любой более сильный селектор, а не тип раскладки.
</details>

<details>
<summary>3. Почему в <code>claimName</code> стоит <code>location.reload()</code>, а не переход на комнату?</summary>

- **а)** Чтобы сервер успел записать аккаунт на диск.
- **б)** Чтобы перезапустить SSE-соединение с новым токеном.
- **в)** Чтобы адрес остался тем же и `?join=` дожил до второго прохода — вся
  поломка была в том, что приглашение теряется при уходе со страницы. ✓
- **г)** Потому что `renderRoom` нельзя вызвать до `API.load()`.

Правильный ответ — **в**. Смысл починки — не уводить человека оттуда, где лежит
контекст; перезагрузка тем же адресом даёт это бесплатно и одинаково работает для
`?join=`, `?solo=`, `?quick=` и `?create=`. Побочно верно и **б**, но это следствие,
а не причина: то же можно было сделать без перезагрузки. **а** неверно — запись
аккаунта идёт отложенно и на клиента не влияет.
</details>

<details>
<summary>4. Что именно ищет проверка мёртвых правил в тесте гигиены?</summary>

- **а)** Любое дублирование селектора в файле.
- **б)** Селектор из `@media`, у которого то же свойство объявлено ниже в файле и
  вне медиазапросов, — при равной специфичности такое объявление отменяет правку. ✓
- **в)** Правила с `!important` внутри медиазапросов.
- **г)** Медиазапросы, вложенные друг в друга.

Правильный ответ — **б**. Важны все три условия: **ниже** (иначе побеждает
медиазапрос), **вне медиазапросов** (иначе правила могут просто не пересекаться по
условию) и **то же свойство** (разные свойства друг друга не отменяют). Поэтому
же правила с `!important` из проверки исключены — такое переспорит и позднее
объявление, то есть мёртвым не будет. Вариант **а** дал бы море ложных срабатываний:
дополнять селектор ниже — обычное дело.
</details>

<details>
<summary>5. Зачем в <code>stage3d.js</code> вместе с выходом по <code>document.hidden</code> сбрасывается <code>last = 0</code>?</summary>

- **а)** Иначе `requestAnimationFrame` не возобновится после разворачивания.
- **б)** Иначе первый кадр после возвращения даст огромный `dt`, счётчик кадров
  примет это за слабое железо и понизит качество сцены на всю партию. ✓
- **в)** Чтобы плавная смена света начиналась заново.
- **г)** Чтобы обнулить накопленный `fpsAcc`.

Правильный ответ — **б**. В кадре есть самонастройка: если средний счёт кадров
падает ниже 34, сцена один раз и навсегда понижает уровень качества. Пауза длиной
